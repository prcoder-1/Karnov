# Karnov — каталог врагов и AI handler'ов

Этот файл — результат полного reverse-engineering AI системы Karnov.
Все 57 AI handler'ов декомпилированы и сопоставлены с реальными спрайтами
из файла `SPRITES.EGA`.

> **Важно**: см. также `ENEMY_GUIDE_CORRECTIONS.md` — там приведены
> корректировки этого документа на основе перечитывания `KARNOV.TXT`.
> KARNOV.TXT каноническими именами врагов называет только **Ryu**;
> все остальные имена (типа «голем», «змея», «зомби») — мои спекуляции
> и должны восприниматься как гипотезы.

## Ключевое открытие: SPRITES.EGA содержит привязку sprite → AI type

Директория SPRITES.EGA имеет следующий формат (после RLE-распаковки):

```c
struct SpriteDirectory {
    uint16_t  total_sprites;          // = 338
    struct {
        uint16_t  ai_handler_type;     // ← AI type, использующий этот спрайт!
        uint16_t  data_offset;         // смещение пиксельных данных
        uint8_t   reserved[4];
    } entries[338];
};
```

Поле, которое я считал «размером», на самом деле — **AI handler type ID**.
Это позволяет ОБРАТНО восстановить, какие спрайты принадлежат каждому
типу врага.

## Семейства handler'ов (общие helper'ы)

### Семейство «класса 9» — крупные враги с helper `0x11D6:0x4B36`
- type 9 (2-bbox, 0x091-0x092)
- type 19 (1-bbox, 0x0AC)
- type 37 (3 sprites)

**Гипотеза**: семейство **«Голем / стационарный страж»** — крупные
неподвижные/медленные враги, использующие общий движок для повторных
анимаций.

### Семейство Karnov-управляемых (читают direction_bits)
- type 2 — основная физика (×2 acc)
- type 3 — плавание/полёт (÷2 acc)

### Семейство «Spawn FX» (`cs:0xD4B:0x19F`)
14 handler'ов (типы 11, 14, 17, 24, 28, 29, 31, 32, 44, 46, 48, 54, 55):
все вызывают «появись красиво» помощник перед основной AI логикой.

### Семейство «PRNG» (`cs:0x1CE7:0x17`)
6 handler'ов (типы 6, 8, 25, 44, 45, 47): используют random_number_generator
для непредсказуемости.

### Семейство Player-tracker (читают `[DS:0xD95F]`)
12 handler'ов (типы 11, 13, 14, 15, 16, 18, 23, 26, 28, 36, 40, 46):
следят за позицией игрока.

## Подробные профили ключевых врагов

### ★★★ Ryu (Type 36) — Финальный босс

```
File offset:  0x16FBB
EXE address:  cs:0x151A:0x061B
AI handler:   ai_type36()
Sprites:      0x0F5, 0x0F6, 0x0F7, 0x0F8, 0x0F9, 0x0FA (6 кадров)
Structure:    2-bbox (одновременно показывает 2 части)
                bbox[0] = 0xF5 (тело/голова)
                bbox[1] = 0xF9 (хвост/вторая часть)
HP:           неизвестно, но state 5 — особое HURT-FX (мигание)
Behavior:     6 state-веток (включая уникальный state 5 для damage flash)
              x_world выровнен по 8-пиксельной сетке
              Ассистент: type 49 (LEVEL9 + x > 0x44C)
Helpers:      cs:0xD4B:0x1124 (звук), cs:0x41D:0x4D7 (FX)
Story:        KARNOV.TXT — «huge and evil dragon, has stolen the Treasure
              of Babylon». Игрок сражается с ним в финале.
```

Промежуточные кадры 0xF6-0xF8 объясняют **6-кадровую анимацию Ryu**:
- 0xF5: голова влево (idle)
- 0xF6: голова прямо
- 0xF7: дыхание огнём кадр 1
- 0xF8: дыхание огнём кадр 2
- 0xF9: хвост
- 0xFA: hurt flash

| Sprite | Item |
|--------|------|
| 0x27 | **Boots** (×2 jump) |
| 0x28 | **Bomb** |
| 0x29 | **Ladder** |
| 0x2A | **Boomerang** |
| 0x2B | **Clapper** (kills all enemies) |
| 0x2C | **Glasses** (reveals hidden items) |
| 0x2D | **Swimming Mask** (LEVEL5) |
| 0x2E | **Wings** (LEVEL8) |
| 0x2F | **Shield** (5 hits) |

Type 6 имеет режим «invisible» (misc_state >= 11) — это **СКРЫТЫЕ

### Items pickup → Bonus drop (Types 5 ↔ 6 ↔ 4)

Найдена связь:
- Type 1 (Karnov idle animation transition) → queue_state → **Type 4**
- Type 4 INIT использует `cs:0xFFA:0x677` — тот же RNG-помощник что и type 5!
- Type 5 (падающий бонус) и Type 6 (визуальный бонус) делят sprite range 0x27..0x32

Это **система предметов**:
- Type 6 — предмет, лежащий в мире (некоторые скрыты)
- Type 5 — предмет, падающий после убийства врага
- Type 4 — анимация трансформации (frame-gated каждые 16 кадров)

### Final-arena helpers (Type 49)

Type 49 имеет **жёстко закодированную проверку LEVEL9**:
```c
if (max_level_reached == 9 && obj.x_world > 0x44C):
    // активировать Ryu helper mode
```

С 2 спрайтами (0x130, 0x131) это **boss arena minion** или **подспорье
Ryu** (например, его «слуги», атакующие игрока пока вы сражаетесь с
драконом).

## Reverse-engineering верификация

Кросс-валидация архитектуры:
1. **`level_enemies[0]` = Karnov** — первая запись каждого уровня
   использует type 2 (Karnov), что подтверждается отсутствием sprite
   0xN handler'а для type 2 (Karnov-frames в category 512+, а не как
   spr→type 2).

2. **Sprite_id из ai_typeNN INIT** ⊂ **полный sprite set типа NN**:
   - ai_type09 INIT: bbox[0]=0x91 — присутствует в type 9 группе ✓
   - ai_type19 INIT: bbox[0]=0xAC — присутствует в type 19 группе ✓
   - ai_type21 INIT: bbox[0]=0xB2 — присутствует в type 21 группе ✓
   - ai_type36 INIT: bbox[0]=0xF5, bbox[1]=0xF9 — оба в type 36 группе ✓
   - ai_type50 INIT: bbox[i]=0x132 — присутствует в type 50 ✓

Все handler'ы используют sprite_ids, попадающие в их же category — это
**доказательство правильности декомпиляции**.
